peko keys <add|generate|p12|verify|list|remove|install|set-password> [OPTIONS]

SUBCOMMANDS
    add            register key files and a password you already have
    generate       create new signing material (android keystore, or an
                   Apple key and certificate request)
    p12            combine an Apple .cer with the kept key into a .p12
    verify         check each platform's material and report what is
                   required, present, and valid
    list           show the registered keys
    remove         delete a platform's keys
    install        register a key file by path, or by name with its bytes
                   on stdin (used by the IDE's drag and drop)
    set-password   store or replace a role's password

Manages the per-project signing keys used to sign release builds. Key
files are copied into .peko/keys/<platform>/ and passwords are stored
in the operating system keychain. The add subcommand registers a
platform's key files and password, list shows the registered keys, and
remove deletes a platform's keys.

`generate` creates signing material rather than registering material you
already have, and `p12` completes the Apple flow. Both work from any host:

    peko keys generate --platform android --password-file pw.txt
        Creates an upload keystore with the bundled JDK's keytool, then
        registers it. Back this file up: Play ties the app listing to it,
        and updates cannot be signed with a different key.

    peko keys generate --platform apple --email you@example.com
        Creates an RSA key and a certificate signing request. Upload the
        .certSigningRequest at developer.apple.com > Certificates, then
        download the .cer it issues.

    peko keys p12 --platform ios --cer downloaded.cer --password-file pw.txt
        Pairs that .cer with the key kept from the request, producing the
        .p12 the bundler signs with, and registers it. Add --installer for
        the macOS Mac Installer Distribution certificate.

Not every platform signs. `verify` reports each platform's requirement:
Apple and Android must be signed to ship, Windows Authenticode is
optional (an unsigned .exe still runs), and Linux has no signing model.
Only a required platform can fail the command.

OPTIONS
    --platform <PLATFORM>     target platform: android, ios, macos, or
                              windows (required for add and remove)
    --password <VALUE>        password for the key file
    --password-file <PATH>    read the key file password from a file
    --keystore <PATH>         android: Java keystore file
    --alias <NAME>            android: key alias in the keystore
                              (defaults to upload)
    --store-password <VALUE>  android: keystore password (defaults to
                              --password)
    --key-password <VALUE>    android: key password (defaults to
                              --password)
    --cert <PATH>             ios and macos: signing certificate as a .p12
    --profile <PATH>          ios: provisioning profile (.mobileprovision)
    --entitlements <PATH>     ios and macos: entitlements plist (optional)
    --notary-issuer <ID>      macos: App Store Connect API issuer id, for
                              notarization (optional)
    --notary-key-id <ID>      macos: App Store Connect API key id (optional)
    --notary-p8 <PATH>        macos: App Store Connect API .p8 private key
                              (optional; required with the notary id flags)
    --pfx <PATH>              windows: code signing certificate as a .pfx
    --cer <PATH>              p12: the certificate downloaded from Apple
    --installer               p12: build the macOS installer certificate
                              instead of the app signing one
    --email <ADDRESS>         generate: the Apple ID the request is for
    --name <NAME>             generate: common name (defaults to --email)
    --country <CODE>          generate: two-letter country (defaults to US)
    --dname <DN>              generate: android distinguished name
    --validity <DAYS>         generate: android key validity (default 10000)
    --out <PATH>              generate and p12: write the output here
    --installer-cert <PATH>   add: macos Mac Installer Distribution
                              certificate, for the App Store .pkg
    --installer-password <V>  add: password for --installer-cert
    --installer-password-file <PATH>  read it from a file
    --role <NAME>             install and set-password: which slot to
                              write (keystore, p12, profile, pfx,
                              installer-p12)
    --file <PATH>             install: the file to register
    --filename <NAME>         install: the name to store the bytes read
                              from stdin under
    --json                    verify: print the report as JSON

EXAMPLES
    peko keys add --platform android --keystore upload.keystore --alias upload --password secret
    peko keys add --platform ios --cert dist.p12 --profile app.mobileprovision --password secret
    peko keys add --platform macos --cert devid.p12 --notary-issuer ISSUER --notary-key-id KEYID --notary-p8 AuthKey.p8 --password secret
    peko keys add --platform windows --pfx codesign.pfx --password secret
    peko keys list
    peko keys remove --platform windows
